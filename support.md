# Support

Premortem is built and supported by one developer, and this page says plainly
what that means for you, so nobody has to guess.

---

## How to reach us

**Email:** alexeyshipin2@gmail.com — for anything: a bug, a question, a risk
assessment that came back useless, a feature you need.

**Security issues:** the same address. Please say "security" in the subject
and, if you can, include steps to reproduce. What happens next is written
down: how a report is triaged, the fix windows we hold ourselves to, and who
gets told, in [the privacy policy](privacy.md#how-the-app-is-secured).

## Hours

**Monday to Friday**, best effort, replies within **2 business days**.

We do not run a 24/7 desk and we are not going to pretend otherwise. A
critical security report is the exception: that is picked up as soon as it is
seen, weekend or not.

## Before you write

These answer most of what arrives:

- **[Troubleshooting](troubleshooting.md)** — the failures people actually
  hit, in the order they hit them.
- **[Settings reference](settings.md)** — what each option costs and when to
  change it.
- **[Getting started](getting-started.md)** — install, key, first assessment.

If the assessments feel generic, that is the expected starting state and
[two settings fix it](troubleshooting.md#assessments-are-generic-and-could-apply-to-any-project).

## What we need from you

A bug report that can be acted on, which usually means:

- the issue key and your site URL (we cannot see either — the app runs on your
  site, not ours);
- which provider and model are configured;
- what you expected and what happened instead;
- the text under the assessment, if there is an error message.

We never ask for your API key, and you should never send it to us. If
something looks like it needs one to reproduce, we will say so and explain how
to test it yourself.
